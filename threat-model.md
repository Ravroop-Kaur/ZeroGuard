# Threat model (prototype)

Scope: the deployed ZeroGuard web service. Assets: protected resources, policy definitions, the audit log, the admin interface.

| # | Threat | Mitigation in this project | Remaining gap |
|---|---|---|---|
| 1 | Client claims a higher role, MFA or device status | Role, MFA and device posture are read from the server database; request bodies and extra headers are ignored (tested) | None for these fields |
| 2 | Impersonating a user | Password (scrypt) plus signed 30-minute tokens; `none`/other algorithms and bad signatures rejected; 5-failure lockout; MFA proven per session by TOTP (tested) | Shared demo password, in-memory lockout, token in sessionStorage; no external IdP |
| 3 | Using someone else's device ID | A device must belong to the requesting user, otherwise it counts as non-compliant (tested) | Posture is simulated; real use needs endpoint attestation |
| 4 | Privilege escalation to admin pages | Admin role check plus a shared `ADMIN_KEY` when deployed; failed attempts are logged | One shared key, no per-admin accounts |
| 5 | Policy engine unavailable or returns junk | Fail closed: any error or invalid effect becomes DENY (tested) | No alert on repeated engine failures |
| 6 | Conflicting rules grant access by accident | Fixed precedence DENY > STEP_UP > ALLOW; one deterministic winner; default deny (Rego-tested) | No policy conflict analysis tooling |
| 7 | Editing past audit records | Hash chain detects any edited or reordered row (tested) | An attacker with full database write access could rebuild the chain; needs external anchoring or write-once storage |
| 8 | Exposing OPA's API | OPA listens on `127.0.0.1` inside the container; only FastAPI is public | No authentication on OPA itself |
| 9 | Spam or brute force on `/access-request` | None | Add rate limiting; log growth is unbounded |
| 10 | Script injection through logged values | React escapes output; fallback page escapes values; CSV export neutralises leading `= + - @` | Add a Content-Security-Policy header |
| 11 | Secret leakage | `ADMIN_KEY` is an environment variable generated by Render; nothing secret is stored in the log | Rotate the key; use a secrets manager beyond demos |
| 12 | Loss of audit data | None on the free instance (SQLite resets on restart) | PostgreSQL with backups and retention |

Out of scope: denial of service, supply-chain attacks, network-level attacks, real MFA enrolment (represented by a stored flag).
